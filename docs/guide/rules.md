# 转发规则

在「转发规则」添加规则，选择 TCP 或 UDP，再选择入口、出口，填写监听端口与目标地址，保存并启用。监听端口留空会自动分配。

同时转发 TCP 和 UDP 时，分别创建两条规则；同一个入口的 TCP 与 UDP 规则可使用相同监听端口。

升级时，原有合并规则自动拆成 TCP、UDP 两条，保留入口、端口、出口、目标和启停状态，各占一个规则名额。历史合计用量留在原 TCP 规则，UDP 规则从零开始统计；用户已用流量不变。导入旧版合并规则备份时也会自动拆分。

目标一行一个，支持域名、IPv4、IPv6：

```text
example.com:443
192.0.2.10:25565
[2001:db8::10]:443
```

以上地址仅为格式示例，请替换真实目标；`192.0.2.0/24`、`2001:db8::/32` 等文档保留网段默认被目标 IP 限制禁止。

客户端连接规则显示的入口地址与端口。直转时选择「不使用隧道，直接转发」；使用出口见 [节点中转](./tunnel.md)。

入口可以选择单个节点或已授权的节点组。选择节点组时，同一条规则会下发到组内启用入口功能的节点，并在各节点使用相同监听端口；节点加入或移出组后会同步调整。各入口必须允许该端口并满足出口配置，端口冲突时需要先处理冲突。节点临时停用或离线时不再处理流量，恢复后可继续同步。

规则列表显示管理员为入口组设置的连接地址和端口，鼠标移到节点图标可查看各成员地址和状态。入口组不会自动将客户端连接分流；需要自行配置域名解析或外部负载均衡，并确保客户端能够访问对应节点。共享 TLS 入站配置属于单个节点，入口组规则请使用普通 TCP 或 UDP 端口。

限速、IP 数和连接数在每个入口节点分别执行，不是整个入口组的全局上限；多个入口同时使用时，合计可能超过单个节点的限制。流量额度由面板统一分配并计入用户额度。

入口组使用隧道出口时，出口节点需要支持多入口授权（Agent 协议版本 37 或以上）；未升级的出口不会承载该规则。规则列表会显示各入口的同步和可用状态。入口组规则暂不支持批量编辑，请逐条修改；导出时请使用 Nekopass 完整备份。

出口选择框同时列出单个节点和节点组：绿色节点图标表示单个出口，蓝色节点组图标表示一组出口。选择节点组后，入口按组内策略分配新连接，自动使用可用成员及容灾备用。成员、权重和健康检查由管理员在「节点管理 → 节点组」配置。

TCP 连接及 UDP 会话建立后固定出口。连接建立失败时可以尝试其他出口，已经建立的 TCP 连接不会迁移到另一台节点。组内线路共用用户在入口节点上的限速与流量额度，消耗倍率按实际出口计算。

多个 TCP 规则共用端口并按 SNI 分流时，选择「共享 TLS 入站」，配置方法见 [TLS 入站](../security/tls-inbound.md)。

规则支持分组、复制、批量启停和 JSON 导入导出；每个账号只管理自己的规则，管理员在「用户管理」查看其他用户的规则。

## 规则诊断

在规则操作栏点击「规则诊断」图标，可以查看链路拓扑。直转规则显示入口到目标，中转规则分别显示入口到出口、出口到目标；入口组、出口组和多个目标按实际链路展示。拓扑图的颜色随面板浅色或深色主题变化。

绿色表示检测成功，红色表示检测失败，灰色表示未检测或无法确认。TCP 目标检测显示节点到目标的建连耗时；入口到出口显示隧道探测耗时。这些数值不是用户到入口的网络延迟，也不能保证目标应用正常工作。UDP 没有通用的目标响应方式，不能确认时会显示「无法确认」。

节点离线、配置尚未同步或节点版本不支持诊断时，对应链路会显示未检测及原因。诊断需要面板和相关节点都升级到支持此功能的版本；检测结束后可点击「重新诊断」。

## 批量编辑

勾选规则后点击「批量编辑」，可统一修改入口、出口、负载均衡和 Proxy Protocol 开关。留空保持原值，出口选择「不使用隧道，直接转发」表示改为直转。每次最多 500 条，任一规则校验失败时整批不保存。

更换普通规则的入口会重新分配监听端口，选择原入口时保留端口。共享 TLS 规则可批量修改出口、负载均衡和发送 Proxy Protocol；迁移共享入口需逐条编辑，接收 Proxy Protocol 由管理员配置。批量编辑保留每条规则原有的限速；IP 和连接数限制沿用用户个人设置。

弹窗里的「暂停选中规则」「恢复选中规则」直接执行启停；其他字段点击「确定」后保存。管理员在「用户管理 → 转发规则」使用相同功能。

## 暂停与恢复

单条规则点击操作栏的「暂停」图标，再次点击「恢复」即可解除暂停。批量操作先勾选规则，再点击上方「暂停选中」或「恢复选中」。暂停保留规则和已有流量统计，节点同步配置后停止转发并关闭现有连接。

管理员在「用户管理 → 转发规则」使用相同操作；管理员暂停后，用户仍可自行恢复。恢复后仍需满足套餐有效期、额度和节点权限。

## 导入与导出

普通 TCP 规则可导出 nyanpass 兼容格式，一行一个 JSON：

```json
{"dest":["example.com:443"],"listen_port":9122,"name":"示例","proxy_protocol":3}
```

导入时粘贴内容或选择文件，再选择入口、出口和分组。端口 `0` 表示随机分配，也可以勾选「重新随机分配监听端口」。最多 500 条，失败时整批回滚。

`proxy_protocol`：省略或 `0` 为关闭，`1` 为发送 v1 TCP，`3` 为发送 v2 TCP；`2` 按 v2 TCP 导入，当前不支持 UDP。`accept_proxy_protocol: 1` 开启接收，信任来源由管理员在「系统设置 → 转发安全」配置，用户导入的数据不能更改信任网段。

管理员可禁止转发到指定 IPv4 / IPv6 网段，节点会检查域名实际解析出的 IP。默认禁止本机、内网、链路本地、组播、云 metadata 等特殊地址；需要访问内网时，由管理员移除对应限制。

兼容格式不包含节点、分组、启停状态、规则限速和接收版本限制。TLS 入站、回源 TLS、UDP 规则及完整配置使用「Nekopass 完整备份」；旧版备份仍可导入。

## 账号与额度

规则跟随用户当前的个人额度、限速和节点组。套餐仅提供初始值；管理员自己的账号也需要套餐和节点权限。限制留空表示不限制；额度耗尽会停用收费线路，0 倍线路仍可使用，套餐到期时停止所有转发。

规则流量与带宽按双向业务数据合计。额度按入口与出口倍率计算，见 [流量倍率](./nodes.md#流量倍率)。可在每条规则的「高级选项」单独设置规则限速，单位为 Mbps；0 表示该规则不额外限速。管理员为用户设置的单规则限速仍然生效，两个非零限速同时存在时取较小值。

同一用户的所有规则在同一入口节点共享用户带宽上限，即使各规则设置的限速之和超过用户上限，总速率仍受用户上限约束；不同入口节点分别限速。

修改后若实际生效的单规则上限发生变化，节点同步配置时会中断该规则的现有连接或 UDP 会话，新连接按新上限执行。
